# Audit queries and navigation

Production storage remains the Audit JSON files. The private SQLite file `data/audit-query.sqlite` is a disposable read index, not a second writable database. Python's standard SQLite library rebuilds it transactionally when the authoritative entries file's inode, size or modification time changes. Never restore this index in place of the JSON records. A future MongoDB configuration is rejected rather than silently querying stale JSON.

Composite indexes cover project/company/year with stable issue/date/ID ordering, department and status filters. SQL calculates whole-result totals, priorities, department counts, open actions and year counts before returning only the requested page (maximum 100 rows). Literal substring search remains a scan within the selected company/year; a full-text search design is a future option. Export and update lookups no longer use the former 5,000-row listing cap.

An authenticated server result cache is bounded to 100 queries/24 MB, keyed by the current file revision and complete query. Concurrent identical queries share their in-flight work. Browser pages are cached in memory for 15 seconds (maximum 12 pages), invalidated by successful mutations, and separated by company/year/search/page. Out-of-order navigation responses cannot replace the active view. Data Entry does not fetch report data. Tab handlers are assigned once rather than accumulated on each render. The DOM contains only the selected page, and the original PDF iframe is removed.

JSON, JS, CSS and HTML responses support gzip. Static assets and finding pages use private conditional revalidation with weak ETags; authentication runs before any private 304 response. Credentials, settings and other private responses remain no-store. PDF generation runs asynchronously with at most two concurrent jobs and a 120-second limit, keeping navigation responsive. Writes remain serialized; reads wait for preceding writes without serializing independent reads.

Limits: JSON writes and index rebuilds remain proportional to total record volume, as do full exports. This change improves read-heavy reporting and navigation; a large sustained write workload will require migration of the authoritative store, including sync/idempotency state, to a transactional database. The original record files and existing accounts are not migrated by this update.

Validation: `tests/audit-query-index.test.mjs` exercises more than 12,000 records, late pagination, full summaries, actual EXPLAIN index usage, company isolation, concurrent rebuild reads, and invalidation after atomic writes. `tests/audit-navigation-browser.mjs` checks zero report fetches for entry, no duplicate tab queries, warm navigation, delayed-company races, gzip, conditional requests and anonymous cache denial. Existing report and offline-mobile browser tests cover compatibility.
